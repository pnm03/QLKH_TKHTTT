Nhân viên Bán hàng (Actor)
Người dùng cuối thực hiện quy trình bán hàng
Actor là người dùng thực tế trong hệ thống - đại diện cho nhân viên bán hàng, nhân viên kho, hoặc quản trị viên có quyền truy cập module bán hàng.
Vai trò và Quyền hạn
  • NVBH (Nhân viên Bán hàng): Quyền tạo đơn hàng, quản lý khách hàng
  • NVK (Nhân viên Kho): Quyền xem tồn kho, cập nhật sản phẩm
  • Admin: Toàn quyền truy cập tất cả chức năng
Hành động thực hiện
  • Đăng nhập vào hệ thống bằng username/password
  • Điều hướng qua các menu Dashboard
  • Tìm kiếm và chọn sản phẩm
  • Điều chỉnh số lượng sản phẩm
  • Tìm kiếm và chọn khách hàng
  • Quyết định phương thức bán hàng (nhanh/gửi đi)
🔍 Trong code thực tế:
// Không có class cụ thể - đại diện cho user session
// Thông tin lưu trong:
- Supabase Auth Session
- localStorage: user preferences
- sessionStorage: current state

Auth System - Hệ thống Xác thực
Quản lý đăng nhập, phiên làm việc và phân quyền
Auth System là hệ thống xác thực tập trung, sử dụng Supabase Auth để quản lý đăng nhập, session và phân quyền người dùng.
Chức năng chính
  • Authentication: Xác thực username/password
  • Session Management: Quản lý phiên đăng nhập
  • Role Validation: Kiểm tra quyền truy cập
  • Token Refresh: Gia hạn token tự động
Thực thể liên quan trong Database
  • accounts: Lưu thông tin tài khoản (username, role, status)
  • users: Thông tin cá nhân người dùng
  • auth.users: Bảng Supabase Auth (email, password hash)
📁 Trong code thực tế:
// File: utils/supabase/client.ts
export const createClient = () => {
  return createBrowserClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!
  )
}

// File: app/auth/signin/page.tsx
const { data: sessionData, error } = await supabase.auth.signInWithPassword({
  email: data.email,
  password: data.password,
});

// API Route: app/api/auth/signout/route.ts
export async function POST() {
  const supabase = createClient()
  await supabase.auth.signOut()
}

Dashboard Controller - Bộ điều khiển Trang chủ
Quản lý giao diện chính và điều hướng
Dashboard Controller là thành phần quản lý giao diện chính sau khi đăng nhập, xử lý điều hướng menu và kiểm tra quyền truy cập các module.
Trách nhiệm chính
  • Session Verification: Kiểm tra phiên đăng nhập hợp lệ
  • Menu Rendering: Hiển thị menu theo quyền của user
  • Navigation Control: Điều hướng giữa các module
  • Layout Management: Quản lý layout chung của ứng dụng
Tương tác với các thành phần
  • Gọi Auth System để verify session
  • Render menu dựa trên role của user
  • Chuyển hướng đến Sales Controller khi click "Bán hàng"
📁 Trong code thực tế:
// File: app/dashboard/layout.tsx
export default function DashboardLayout({ children }) {
  const [user, setUser] = useState(null)
  
  // Kiểm tra session
  const fetchUserData = async () => {
    const supabase = createClient()
    const { data: { session } } = await supabase.auth.getSession()
    
    if (session?.user) {
      setUser(session.user)
    }
  }
  
  // Navigation menu
  const navigation = [
    { name: 'Tổng quan', href: '/dashboard', icon: HomeIcon },
    { name: 'Bán hàng', href: '/dashboard/sales', icon: ShoppingCartIcon },
    // ... other menu items
  ]
}

Sales Controller - Bộ điều khiển Bán hàng
Xử lý logic nghiệp vụ bán hàng và tạo đơn hàng
Sales Controller là thành phần trung tâm xử lý toàn bộ quy trình bán hàng, từ tạo đơn hàng, quản lý giỏ hàng đến tính toán tổng tiền.
Chức năng core
  • Order Management: Tạo, cập nhật, xóa đơn hàng
  • Cart Operations: Thêm/xóa sản phẩm, cập nhật số lượng
  • Price Calculation: Tính tổng tiền, thuế, giảm giá
  • Stock Validation: Kiểm tra tồn kho trước khi thêm
  • Customer Assignment: Gán khách hàng cho đơn hàng
Methods chính
  • addProductToOrder(product): Thêm sản phẩm vào đơn
  • updateQuantity(index, quantity): Cập nhật số lượng
  • calculateTotal(): Tính tổng tiền
  • selectCustomer(customer): Chọn khách hàng
  • validateStock(productId, quantity): Kiểm tra tồn kho
📁 Trong code thực tế:
// File: app/dashboard/sales/create/page.tsx
const addProductToOrder = (product) => {
  const existingIndex = selectedProducts.findIndex(p => p.product_id === product.product_id)
  
  if (existingIndex >= 0) {
    // Tăng quantity nếu đã có
    updateQuantity(existingIndex, selectedProducts[existingIndex].quantity + 1)
  } else {
    // Thêm mới với quantity = 1
    setSelectedProducts([...selectedProducts, { ...product, quantity: 1 }])
  }
  calculateTotal()
}

const calculateTotal = () => {
  const total = selectedProducts.reduce((sum, product) => {
    return sum + (product.price * product.quantity)
  }, 0)
  setTotalAmount(total)
}

Product Service - Dịch vụ Sản phẩm
Quản lý dữ liệu và logic nghiệp vụ sản phẩm
Product Service là lớp dịch vụ chuyên xử lý các thao tác liên quan đến sản phẩm như tìm kiếm, lọc, kiểm tra tồn kho.
Chức năng chính
  • Product Search: Tìm kiếm sản phẩm theo tên, mã
  • Category Filtering: Lọc theo danh mục
  • Stock Checking: Kiểm tra số lượng tồn kho
  • Price Management: Quản lý giá bán, giá nhập
  • Product Validation: Validate dữ liệu sản phẩm
API Methods
  • searchProducts(searchTerm): Tìm kiếm với ILIKE
  • getProductById(id): Lấy chi tiết sản phẩm
  • checkStock(productId): Kiểm tra tồn kho
  • getProductsByCategory(categoryId): Lọc theo danh mục
Database Tables liên quan
  • products: Thông tin cơ bản sản phẩm
  • categories: Danh mục sản phẩm
  • inventory: Quản lý tồn kho
📁 Trong code thực tế:
// File: app/dashboard/sales/create/page.tsx
const searchProducts = async (searchTerm) => {
  const supabase = createClient()
  
  const { data, error } = await supabase
    .from('products')
    .select(`
      product_id, name, price, stock_quantity,
      categories(category_id, name)
    `)
    .ilike('name', `%${searchTerm}%`)
    .eq('status', 'active')
    .limit(10)
    
  if (error) {
    console.error('Lỗi tìm kiếm sản phẩm:', error)
    return []
  }
  
  return data || []
}

Customer Service - Dịch vụ Khách hàng
Quản lý thông tin và tương tác với khách hàng
Customer Service là lớp dịch vụ xử lý các thao tác liên quan đến khách hàng như tìm kiếm, tạo mới, cập nhật thông tin.
Chức năng chính
  • Customer Search: Tìm kiếm đa trường (tên, SĐT, email)
  • Customer Creation: Tạo khách hàng mới nhanh
  • Profile Management: Cập nhật thông tin khách hàng
  • Order History: Xem lịch sử mua hàng
  • Loyalty Points: Quản lý điểm tích lũy
API Methods
  • searchCustomers(searchTerm): Tìm kiếm khách hàng
  • getCustomerById(id): Lấy chi tiết khách hàng
  • createCustomer(data): Tạo khách hàng mới
  • updateCustomer(id, data): Cập nhật thông tin
Database Tables liên quan
  • customers: Thông tin cơ bản khách hàng
  • customer_addresses: Địa chỉ giao hàng
  • orders: Lịch sử đơn hàng
📁 Trong code thực tế:
// File: app/dashboard/sales/create/page.tsx
const searchCustomers = async (searchTerm) => {
  const supabase = createClient()
  
  const { data, error } = await supabase
    .from('customers')
    .select('customer_id, full_name, phone, email')
    .or(`full_name.ilike.%${searchTerm}%,phone.ilike.%${searchTerm}%,email.ilike.%${searchTerm}%`)
    .limit(5)
    
  if (error) {
    console.error('Lỗi tìm kiếm khách hàng:', error)
    return []
  }
  
  return data || []
}

Database (Supabase) - Cơ sở dữ liệu
PostgreSQL database với Supabase backend
Database là cơ sở dữ liệu PostgreSQL được quản lý bởi Supabase, lưu trữ toàn bộ dữ liệu của hệ thống QLBH.
12 Bảng chính trong hệ thống
  • users: Thông tin cá nhân người dùng
  • accounts: Tài khoản đăng nhập và phân quyền
  • branches: Thông tin chi nhánh
  • categories: Danh mục sản phẩm
  • products: Sản phẩm và thông tin
  • customers: Khách hàng
  • orders: Đơn hàng
  • order_items: Chi tiết sản phẩm trong đơn
  • shipments: Thông tin vận chuyển
  • payments: Thanh toán
  • payment_methods: Phương thức thanh toán
  • returns: Đổi trả hàng
Tính năng Supabase được sử dụng
  • Supabase Auth: Xác thực và phân quyền
  • Row Level Security: Bảo mật cấp dòng
  • Real-time: Cập nhật thời gian thực
  • PostgreSQL Functions: Stored procedures
  • Triggers: Tự động cập nhật dữ liệu

🔄 Mối quan hệ và Tương tác giữa các Thực thể
Luồng tương tác chính
  • 1. Authentication Flow:
    👤 Nhân viên → 🔐 Auth System → 🗄️ Database (accounts, users)
  • 2. Dashboard Navigation:
    👤 Nhân viên → 📊 Dashboard Controller → 🔐 Auth System (verify session)
  • 3. Sales Module Access:
    👤 Nhân viên → 🛒 Sales Controller → 🔐 Auth System (check role)
  • 4. Product Operations:
    🛒 Sales Controller → 📦 Product Service → 🗄️ Database (products, categories)
  • 5. Customer Operations:
    🛒 Sales Controller → 👥 Customer Service → 🗄️ Database (customers)
Dependency và Coupling
  • High Coupling: Sales Controller ↔ Product/Customer Services
  • Medium Coupling: Dashboard Controller ↔ Auth System
  • Low Coupling: Services ↔ Database (chỉ qua API calls)
Pattern Architecture được áp dụng
  • MVC Pattern: Controller (Sales) - Model (Services) - View (React Components)
  • Service Layer: Product Service, Customer Service tách biệt logic
  • Repository Pattern: Database access được abstract qua Supabase client
  • Authentication Middleware: Auth System kiểm tra mọi request

Hiểu rõ vai trò từng thực thể trong hệ thống
Sơ đồ tuần tự "Chuẩn bị Bán hàng" thể hiện một quy trình hoàn chỉnh từ đăng nhập đến chuẩn bị tạo đơn hàng. Mỗi thực thể đều có vai trò rõ ràng và tương tác chặt chẽ với nhau.
Điểm mạnh của kiến trúc
  • Separation of Concerns: Mỗi thành phần có trách nhiệm riêng biệt
  • Scalability: Dễ mở rộng thêm tính năng mới
  • Maintainability: Code dễ bảo trì và debug
  • Security: Kiểm tra quyền ở nhiều lớp
Có thể cải thiện
  • Thêm Caching Layer để tối ưu performance
  • Implement Error Boundary cho error handling tốt hơn
  • Áp dụng State Management (Redux/Zustand) cho complex state
  • Thêm Logging Service để track user actions
