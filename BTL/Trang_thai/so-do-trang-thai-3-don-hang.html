Sơ đồ trạng thái - Quản lý Đơn hàng

Mô tả chung

Sơ đồ này mô tả trạng thái thanh toán của đơn hàng trong hệ thống QLBH. Theo database schema, đơn hàng chỉ có 2 trạng thái chính về thanh toán, với logic chuyển đổi dựa trên phương thức thanh toán và vận chuyển.

Các trạng thái đơn hàng (theo database):

  • Chưa thanh toán: Đơn hàng đã tạo nhưng chưa thanh toán (thường COD)
  • Đã thanh toán: Đơn hàng đã thanh toán thành công hoặc thanh toán ngay

Logic chuyển đổi trạng thái (từ code thực tế):

  • Tạo đơn COD: Đơn hàng được tạo với trạng thái "Chưa thanh toán" + payment_method = NULL
  • Tạo đơn Prepaid: Đơn hàng thanh toán ngay với trạng thái "Đã thanh toán" + payment_method ≠ NULL
  • Giao hàng COD thành công: Tự động chuyển từ "Chưa thanh toán" → "Đã thanh toán" + gán payment_method
  • Hoàn trả COD: Khi vận chuyển chuyển về trạng thái chưa giao, COD sẽ về "Chưa thanh toán"
  • Xử lý manual: Admin có thể cập nhật trạng thái thanh toán thủ công

Ràng buộc nghiệp vụ (Database Constraint):

  • Constraint chính: Nếu status = "Chưa thanh toán" thì payment_method phải NULL
  • Constraint chính: Nếu status = "Đã thanh toán" thì payment_method phải ≠ NULL
  • Vận chuyển: Chỉ đơn "Đã thanh toán" mới được tạo shipping record
  • Báo cáo doanh thu: Chỉ tính đơn "Đã thanh toán"
