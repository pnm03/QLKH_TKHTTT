⚡ Sơ đồ Tuần tự - Bán hàng Nhanh

Quy trình thanh toán tại chỗ với in hóa đơn

🎯 Mô tả quy trình Bán hàng Nhanh

  • Điều kiện tiên quyết: Đã hoàn thành quy trình chuẩn bị (chọn sản phẩm, khách hàng)
  • Validation đơn hàng: Kiểm tra tồn kho và tính hợp lệ
  • Chọn phương thức thanh toán: Tiền mặt, thẻ, chuyển khoản
  • Tính toán tiền thối: Nhập số tiền khách trả, tính tiền thối
  • Xác nhận thanh toán: Xử lý thanh toán và tạo đơn hàng
  • Cập nhật database: Tạo order, orderdetails, cập nhật tồn kho
  • In hóa đơn: Hiển thị preview và in hóa đơn bán hàng
  • Reset giao diện: Làm sạch form cho đơn hàng tiếp theo
⚡ PlantUML Sequence Diagram - Bán hàng Nhanh
@startuml Bán hàng Nhanh - QLBH System
!theme plain
skinparam backgroundColor #FFFFFF
skinparam actorBorderColor #2C3E50
skinparam participantBorderColor #28A745
skinparam sequenceArrowColor #E74C3C
skinparam sequenceLifeLineBorderColor #95A5A6

title **QUY TRÌNH BÁN HÀNG NHANH**\n//Thanh toán tại chỗ với in hóa đơn//

actor "👤 Nhân viên\nBán hàng" as Staff
participant "🛒 Sales\nController" as Sales
participant "💳 Payment\nService" as Payment
participant "📊 Order\nService" as Order
participant "📦 Stock\nService" as Stock
participant "🖨️ Invoice\nService" as Invoice
database "🗄️ Database\n(Supabase)" as DB

note over Staff, DB : **ĐIỀU KIỆN TIÊN QUYẾT:**\n• Đã chọn sản phẩm với số lượng\n• Đã chọn khách hàng (hoặc khách vãng lai)\n• Hiển thị tổng tiền cần thanh toán

== KHỞI TẠO BÁN HÀNG NHANH ==

Staff -> Sales : 1. Click "Bán hàng nhanh"
activate Sales
Sales -> Sales : 1.1 validateOrder() - Kiểm tra đơn hàng
note right : Validation:\n• Có sản phẩm trong đơn\n• Số lượng không vượt tồn kho\n• Tính toán lại tổng tiền

alt **Validation thành công**
    Sales -> Sales : 1.2 Tính tổng tiền tất cả hóa đơn
    Sales -> Payment : 1.3 Load payment methods
    activate Payment
    Payment -> DB : 1.3.1 Query payment methods
    activate DB
    DB --> Payment : 1.3.2 Return payment methods list
    deactivate DB
    Payment --> Sales : 1.3.3 Payment methods data
    deactivate Payment
    
    Sales --> Staff : 1.4 Hiển thị popup thanh toán nhanh
else **Validation thất bại**
    Sales --> Staff : ❌ Thông báo lỗi validation
end
deactivate Sales

== CHỌN PHƯƠNG THỨC THANH TOÁN ==

Staff -> Sales : 2. Chọn phương thức thanh toán
activate Sales
Sales -> Sales : 2.1 setSelectedPaymentMethod(paymentId)
Sales --> Staff : 2.2 Hiển thị phương thức đã chọn
deactivate Sales

Staff -> Sales : 3. Nhập số tiền khách trả
activate Sales
Sales -> Sales : 3.1 setCustomerPaid(amount)
Sales -> Sales : 3.2 Tính toán tiền thối
Sales --> Staff : 3.3 Hiển thị tiền thối (real-time)
deactivate Sales

opt **Nhập giảm giá (nếu có)**
    Staff -> Sales : 4. Nhập số tiền giảm giá
    activate Sales
    Sales -> Sales : 4.1 setDiscount(discountAmount)
    Sales -> Sales : 4.2 Tính lại tổng tiền sau giảm giá
    Sales --> Staff : 4.3 Cập nhật hiển thị tổng tiền
    deactivate Sales
end

== XÁC NHẬN THANH TOÁN ==

Staff -> Sales : 5. Click "Xác nhận thanh toán"
activate Sales
Sales -> Sales : 5.1 Validation thanh toán
note right : Kiểm tra:\n• Đã chọn phương thức thanh toán\n• Số tiền khách trả ≥ tổng tiền\n• Thông tin hợp lệ

alt **Validation thanh toán OK**
    Sales --> Staff : 5.2 Hiển thị popup xác nhận chi tiết
    note right : Popup xác nhận:\n• Chi tiết sản phẩm\n• Thông tin thanh toán\n• Số tiền khách trả\n• Tiền thối
    deactivate Sales
    
    Staff -> Sales : 6. Click "Xác nhận" trong popup
    activate Sales
    Sales -> Order : 6.1 Bắt đầu tạo đơn hàng
    activate Order
    
    == TẠO ĐƠN HÀNG VÀ CẬP NHẬT DATABASE ==
    
    Order -> Order : 6.2 Tạo order_id ngẫu nhiên
    note right : Format: ORD-YYYYMMDD-XXXXX
    
    Order -> DB : 6.3 Tạo bản ghi Orders
    activate DB
    DB --> Order : 6.4 Confirm order created
    
    Order -> Order : 6.5 Tạo order details
    loop **Cho mỗi sản phẩm trong đơn**
        Order -> Order : 6.5.1 Tạo orderdetail_id
        Order -> DB : 6.5.2 INSERT orderdetails
        activate DB
        DB -> DB : 6.5.3 🔥 TRIGGER: Cập nhật stock_quantity
        DB --> Order : 6.5.4 Confirm orderdetail created
        deactivate DB
    end
    
    deactivate DB
    Order --> Sales : 6.6 Đơn hàng tạo thành công
    deactivate Order
    
    Sales --> Staff : 6.7 Thông báo "Thanh toán thành công"
    
else **Validation thanh toán thất bại**
    Sales --> Staff : ❌ Thông báo lỗi
    deactivate Sales
end

== IN HÓA ĐƠN ==

Staff -> Sales : 7. Click "In hóa đơn" trong popup
activate Sales
Sales -> Invoice : 7.1 Tạo dữ liệu hóa đơn
activate Invoice
Invoice -> Invoice : 7.2 Format invoice data
Invoice --> Sales : 7.3 Invoice data prepared
deactivate Invoice
Sales --> Staff : 7.4 Hiển thị preview hóa đơn
deactivate Sales

Staff -> Sales : 8. Click "In" trong preview
activate Sales
Sales -> Invoice : 8.1 Gọi chức năng in
activate Invoice
Invoice -> Invoice : 8.2 Thêm CSS cho print
Invoice -> Invoice : 8.3 window.print()
Invoice --> Staff : 8.4 Mở dialog in của browser
deactivate Invoice
deactivate Sales

== RESET VÀ CHUẨN BỊ ĐƠN TIẾP THEO ==

Staff -> Sales : 9. Đóng popup (sau khi in)
activate Sales
Sales -> Sales : 9.1 Reset hóa đơn hiện tại
note right : Reset state:\n• Xóa sản phẩm khỏi hóa đơn\n• Clear thông tin khách hàng\n• Reset tổng tiền = 0\n• Clear selected customer

Sales -> Stock : 9.2 Refresh product data
activate Stock
Stock -> DB : 9.2.1 Reload products với stock mới
activate DB
DB --> Stock : 9.2.2 Updated product data
deactivate DB
Stock --> Sales : 9.2.3 Cập nhật tồn kho hiện tại
deactivate Stock

Sales --> Staff : 9.3 Hiển thị giao diện sạch
note right : Sẵn sàng cho đơn hàng tiếp theo:\n• Form trống\n• Tồn kho đã cập nhật\n• Thông báo "Giao dịch hoàn tất"
deactivate Sales

note over Staff, DB : **KẾT QUẢ:**\n• Đơn hàng đã được tạo và thanh toán\n• Tồn kho đã được cập nhật\n• Hóa đơn đã được in\n• Sẵn sàng cho giao dịch tiếp theo

@enduml

🔍 Chi tiết kỹ thuật

  • Order ID Generation: Format ORD-YYYYMMDD-XXXXX với 5 ký tự ngẫu nhiên
  • Database Triggers: Tự động cập nhật stock_quantity khi tạo orderdetails
  • Transaction Safety: Sử dụng try-catch để rollback nếu có lỗi
  • Real-time Calculation: Tính tiền thối tức thì khi nhập số tiền
  • Print Functionality: CSS @media print tối ưu hóa cho in ấn
  • State Management: Reset toàn bộ state sau khi hoàn thành giao dịch
  • Stock Refresh: Reload dữ liệu sản phẩm để cập nhật tồn kho mới

💡 Lưu ý quan trọng

  • Validation 2 lớp: Kiểm tra ở frontend và backend
  • Customer optional: Có thể bỏ trống khách hàng cho khách vãng lai
  • Payment methods: Load động từ database, có thể cấu hình
  • Error handling: Hiển thị thông báo lỗi rõ ràng cho user
  • Print preview: Cho phép xem trước trước khi in
  • Multi-invoice: Có thể xử lý nhiều hóa đơn cùng lúc
