📦 Sơ đồ Tuần tự - Tạo đơn gửi đi

Quy trình tạo đơn hàng có vận chuyển với COD

🎯 Mô tả quy trình Tạo đơn gửi đi

  • Điều kiện tiên quyết: Đã hoàn thành quy trình chuẩn bị (chọn sản phẩm, khách hàng)
  • Nhập thông tin người nhận: Tên, SĐT, địa chỉ giao hàng chi tiết
  • Cấu hình vận chuyển: Nhà vận chuyển, thông tin kiện hàng
  • Chọn thanh toán: Trả trước hoặc COD (thu hộ)
  • Tạo đơn hàng: Lưu đơn hàng với trạng thái phù hợp
  • Tạo thông tin vận chuyển: Mã vận đơn, địa chỉ, phí ship
  • Cập nhật tồn kho: Sử dụng database triggers tự động
  • Thông báo thành công: Hiển thị mã đơn hàng và vận đơn
📦 PlantUML Sequence Diagram - Tạo đơn gửi đi
@startuml Tạo đơn gửi đi - QLBH System
!theme plain
skinparam backgroundColor #FFFFFF
skinparam actorBorderColor #2C3E50
skinparam participantBorderColor #007BFF
skinparam sequenceArrowColor #E74C3C
skinparam sequenceLifeLineBorderColor #95A5A6

title **QUY TRÌNH TẠO ĐƠN GỬI ĐI**\n//Đơn hàng có vận chuyển với COD//

actor "👤 Nhân viên\nBán hàng" as Staff
participant "🛒 Sales\nController" as Sales
participant "📦 Shipping\nService" as Shipping
participant "💳 Payment\nService" as Payment
participant "📊 Order\nService" as Order
participant "📍 Address\nValidator" as Address
database "🗄️ Database\n(Supabase)" as DB

note over Staff, DB : **ĐIỀU KIỆN TIÊN QUYẾT:**\n• Đã chọn sản phẩm với số lượng\n• Đã chọn khách hàng (hoặc khách vãng lai)\n• Hiển thị tổng tiền cần thanh toán

== KHỞI TẠO TẠO ĐƠN GỬI ĐI ==

Staff -> Sales : 1. Click "Tạo đơn gửi đi"
activate Sales
Sales -> Sales : 1.1 validateOrder() - Kiểm tra đơn hàng
note right : Validation:\n• Có sản phẩm trong đơn\n• Số lượng không vượt tồn kho\n• Tính toán lại tổng tiền

alt **Validation thành công**
    Sales -> Sales : 1.2 Khởi tạo shipping form
    note right : Nếu đã chọn khách hàng:\n• Auto-fill tên, SĐT từ customer\n• Auto-fill địa chỉ từ hometown
    
    Sales -> Payment : 1.3 Load payment methods
    activate Payment
    Payment -> DB : 1.3.1 Query payment methods
    activate DB
    DB --> Payment : 1.3.2 Return payment methods list
    deactivate DB
    Payment --> Sales : 1.3.3 Payment methods data
    deactivate Payment
    
    Sales --> Staff : 1.4 Hiển thị popup thông tin vận chuyển
else **Validation thất bại**
    Sales --> Staff : ❌ Thông báo lỗi validation
end
deactivate Sales

== NHẬP THÔNG TIN NGƯỜI NHẬN ==

Staff -> Sales : 2. Nhập tên người nhận
activate Sales
Sales -> Sales : 2.1 setRecipientName(name)
Sales --> Staff : 2.2 Cập nhật form
deactivate Sales

Staff -> Sales : 3. Nhập số điện thoại người nhận
activate Sales
Sales -> Sales : 3.1 setRecipientPhone(phone)
Sales -> Sales : 3.2 Validate phone format
alt **Phone hợp lệ**
    Sales --> Staff : 3.3 Hiển thị valid
else **Phone không hợp lệ**
    Sales --> Staff : ❌ Hiển thị lỗi format
end
deactivate Sales

Staff -> Sales : 4. Nhập địa chỉ giao hàng
activate Sales
Sales -> Sales : 4.1 setRecipientAddress(address)
Sales -> Address : 4.2 validateAddress(address)
activate Address
Address -> Address : 4.2.1 Kiểm tra độ dài và format
Address --> Sales : 4.2.2 Validation result
deactivate Address
Sales --> Staff : 4.3 Cập nhật validation status
deactivate Sales

opt **Nhập thông tin kiện hàng chi tiết**
    Staff -> Sales : 5. Nhập thông tin kiện hàng
    activate Sales
    Sales -> Sales : 5.1 setPackageInfo(weight, dimensions)
    Sales --> Staff : 5.2 Cập nhật form
    deactivate Sales
end

== CHỌN PHƯƠNG THỨC THANH TOÁN ==

alt **Chọn thanh toán trước**
    Staff -> Sales : 6a. Chọn phương thức thanh toán
    activate Sales
    Sales -> Sales : 6a.1 setSelectedPaymentMethod(paymentId)
    Sales -> Sales : 6a.2 setCustomerPrepaid(amount)
    Sales --> Staff : 6a.3 Hiển thị thông tin thanh toán
    deactivate Sales
    
else **Chọn COD (Thu hộ)**
    Staff -> Sales : 6b. Tick checkbox COD
    activate Sales
    Sales -> Sales : 6b.1 setCodShipping(true)
    Sales -> Sales : 6b.2 setCodAmount(totalAmount)
    Sales --> Staff : 6b.3 Hiển thị COD amount
    deactivate Sales
end

== XÁC NHẬN VÀ TẠO ĐƠN HÀNG ==

Staff -> Sales : 7. Click "Xác nhận tạo đơn"
activate Sales
Sales -> Sales : 7.1 Final validation
note right : Kiểm tra cuối:\n• Thông tin người nhận đầy đủ\n• Địa chỉ hợp lệ\n• Phương thức thanh toán hoặc COD\n• Thông tin kiện hàng

alt **Final validation OK**
    Sales -> Order : 7.2 Bắt đầu tạo đơn hàng
    activate Order
    
    == TẠO ĐƠN HÀNG VÀ THÔNG TIN VẬN CHUYỂN ==
    
    Order -> Order : 7.3 Tạo order_id và shipping_id
    note right : Generate IDs:\n• order_id: ORD-YYYYMMDD-XXXXX\n• shipping_id: SHIP-YYYYMMDD-XXXXX
    
    Order -> DB : 7.4 Tạo bản ghi Orders
    activate DB
    DB --> Order : 7.5 Confirm order created
    
    Order -> Order : 7.6 Tạo order details
    loop **Cho mỗi sản phẩm trong đơn**
        Order -> Order : 7.6.1 Tạo orderdetail_id
        Order -> DB : 7.6.2 INSERT orderdetails
        activate DB
        DB -> DB : 7.6.3 🔥 TRIGGER: Cập nhật stock_quantity
        DB --> Order : 7.6.4 Confirm orderdetail created
        deactivate DB
    end
    
    Order -> Shipping : 7.7 Tạo thông tin vận chuyển
    activate Shipping
    Shipping -> Shipping : 7.7.1 Tạo tracking number
    note right : Generate tracking:\nTRK-YYYYMMDD-XXXXX
    
    Shipping -> DB : 7.7.2 INSERT shipping record
    activate DB
    DB --> Shipping : 7.7.3 Confirm shipping created
    deactivate DB
    Shipping --> Order : 7.7.4 Shipping info created
    deactivate Shipping
    
    deactivate DB
    Order --> Sales : 7.8 Đơn hàng + vận chuyển tạo thành công
    deactivate Order
    
    Sales --> Staff : 7.9 Thông báo thành công
    
else **Final validation thất bại**
    Sales --> Staff : ❌ Thông báo lỗi chi tiết
    deactivate Sales
end

== RESET VÀ CHUẨN BỊ ĐƠN TIẾP THEO ==

Staff -> Sales : 8. Đóng popup thành công
activate Sales
Sales -> Sales : 8.1 Reset form tạo đơn
note right : Reset state:\n• Xóa sản phẩm khỏi hóa đơn\n• Clear thông tin khách hàng\n• Clear thông tin vận chuyển\n• Reset tổng tiền = 0

Sales -> Sales : 8.2 Refresh product data
Sales -> DB : 8.2.1 Reload products với stock mới
activate DB
DB --> Sales : 8.2.2 Updated product data với tồn kho mới
deactivate DB

Sales --> Staff : 8.3 Hiển thị giao diện sạch
note right : Sẵn sàng cho đơn hàng tiếp theo:\n• Form trống\n• Tồn kho đã cập nhật\n• Thông báo "Đơn hàng đã tạo"
deactivate Sales

== THEO DÕI ĐƠN HÀNG (Optional) ==

opt **Nhân viên muốn xem chi tiết đơn vừa tạo**
    Staff -> Sales : 9. Click "Xem chi tiết đơn"
    activate Sales
    Sales -> Order : 9.1 getOrderDetails(orderId)
    activate Order
    Order -> DB : 9.1.1 Query order + shipping info
    activate DB
    DB --> Order : 9.1.2 Complete order data
    deactivate DB
    Order --> Sales : 9.1.3 Order details
    deactivate Order
    Sales --> Staff : 9.2 Hiển thị popup chi tiết đơn
    note right : Popup chi tiết:\n• Thông tin đơn hàng\n• Trạng thái vận chuyển\n• Link tracking\n• Lịch sử cập nhật
    deactivate Sales
end

note over Staff, DB : **KẾT QUẢ:**\n• Đơn hàng có vận chuyển đã được tạo\n• Thông tin vận chuyển đã được lưu\n• Tồn kho đã được cập nhật\n• Tracking number đã được tạo\n• Sẵn sàng cho xử lý vận chuyển

@enduml

🔍 Chi tiết kỹ thuật

  • Shipping ID Generation: Format SHIP-YYYYMMDD-XXXXX với 5 ký tự ngẫu nhiên
  • Tracking Number: Format TRK-YYYYMMDD-XXXXX tự động tạo
  • Address Validation: Kiểm tra độ dài tối thiểu và format địa chỉ
  • Phone Validation: Bắt đầu bằng 0, có 10-11 số
  • COD Support: Thu hộ tiền với trạng thái "Chưa thanh toán"
  • Prepaid Option: Thanh toán trước với trạng thái "Đã thanh toán"
  • Package Info: Lưu thông tin kích thước và cân nặng kiện hàng
  • Unique Constraint: Mỗi order chỉ có 1 shipping record (UNIQUE order_id)

📋 Luồng dữ liệu

  • Orders Table: Lưu thông tin đơn hàng với is_shipping = true
  • Orderdetails Table: Chi tiết sản phẩm với trigger cập nhật tồn kho
  • Shippings Table: Thông tin vận chuyển với foreign key đến Orders
  • Status Flow: Chưa giao hàng → Đang chuẩn bị → Đang giao hàng → Đã giao hàng
  • Payment Status: Phụ thuộc vào COD hay thanh toán trước
  • Tracking: Mã vận đơn duy nhất cho theo dõi

💡 Tính năng đặc biệt

  • Auto-fill Customer Info: Tự động điền thông tin nếu đã chọn khách hàng
  • Multiple Payment Options: COD hoặc thanh toán trước
  • Package Dimensions: Lưu thông tin chi tiết kiện hàng
  • Delivery Date Estimation: Tự động tính ngày giao dự kiến
  • Carrier Selection: Hỗ trợ nhiều nhà vận chuyển (GHN, ViettelPost, etc.)
  • Real-time Validation: Kiểm tra thông tin nhập liệu tức thì
