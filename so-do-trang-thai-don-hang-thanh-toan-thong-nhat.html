Thống nhất với UC, AD và Sequence Diagrams - QLBH System

📋 Thông tin sơ đồ

  • Đối tượng: Đơn hàng (Order) với trạng thái thanh toán
  • Thống nhất với: UC Tìm kiếm/Ghi nhận đơn hàng, AD Quản lý đơn hàng, Sequence Diagrams
  • Tích hợp: Trạng thái đơn hàng + Trạng thái thanh toán + Trạng thái vận chuyển
  • Dựa trên: Chức năng thực tế trong ứng dụng QLBH

title Sơ đồ Trạng thái: Đơn hàng và Thanh toán (Thống nhất UC/AD/Sequence)

note top
  Thống nhất với:
  • UC: Tìm kiếm đơn hàng, Ghi nhận đơn hàng
  • AD: Quản lý đơn hàng, Ghi nhận đơn hàng  
  • Sequence: Thanh toán, Tìm kiếm, Bán hàng
  
  Dựa trên chức năng thực tế:
  • Tạo đơn hàng (Quick Sale/Shipping)
  • Thanh toán đơn chưa thanh toán
  • Quản lý trạng thái vận chuyển
end note

[*] --> DangTao : Khách hàng đặt hàng

state "Đang tạo" as DangTao {
    DangTao : entry / Khởi tạo đơn hàng
    DangTao : do / Thu thập thông tin
    DangTao : exit / Validate dữ liệu
}

state "Chờ xác nhận" as ChoXacNhan {
    ChoXacNhan : entry / Gửi thông báo cho nhân viên
    ChoXacNhan : do / Chờ nhân viên xử lý
}

state "Chưa thanh toán" as ChuaThanhToan {
    ChuaThanhToan : entry / Tạo record trong DB
    ChuaThanhToan : do / Hiển thị trong danh sách chờ thanh toán
    ChuaThanhToan : exit / Chuẩn bị thanh toán
}

state "Đang thanh toán" as DangThanhToan {
    DangThanhToan : entry / Khởi tạo payment session
    DangThanhToan : do / Xử lý với payment gateway
    DangThanhToan : exit / Xác nhận kết quả
}

state "Đã thanh toán" as DaThanhToan {
    DaThanhToan : entry / Cập nhật payment_method
    DaThanhToan : do / Sẵn sàng vận chuyển
}

state "Đang vận chuyển" as DangVanChuyen {
    state "Đang chuẩn bị" as DangChuanBi
    state "Đang giao" as DangGiao
    state "Đã giao" as DaGiao
    
    [*] --> DangChuanBi
    DangChuanBi --> DangGiao : Shipper nhận hàng
    DangGiao --> DaGiao : Giao thành công
    DangGiao --> DangHoanVe : Giao thất bại
}

state "Đang hoàn về" as DangHoanVe {
    DangHoanVe : entry / Thông báo khách hàng
    DangHoanVe : do / Shipper hoàn hàng về kho
}

state "Đã hủy" as DaHuy {
    DaHuy : entry / Hoàn tiền (nếu đã thanh toán)
    DaHuy : do / Cập nhật tồn kho
}

state "Hoàn thành" as HoanThanh {
    HoanThanh : entry / Ghi nhận doanh thu
    HoanThanh : do / Có thể tạo đánh giá
}

state "Yêu cầu đổi trả" as YeuCauDoiTra {
    state "Đang xử lý đổi trả" as DangXuLyDoiTra
    state "Đã chấp nhận đổi trả" as DaChapNhanDoiTra  
    state "Đã từ chối đổi trả" as DaTuChoiDoiTra
    
    [*] --> DangXuLyDoiTra
    DangXuLyDoiTra --> DaChapNhanDoiTra : Chấp nhận [hàng còn tốt]
    DangXuLyDoiTra --> DaTuChoiDoiTra : Từ chối [hàng hỏng/quá hạn]
}

' Transitions chính
DangTao --> ChoXacNhan : Hoàn tất thông tin [thông tin hợp lệ]
DangTao --> DaHuy : Hủy tạo [khách hàng hủy]

ChoXacNhan --> ChuaThanhToan : Nhân viên chấp nhận [đơn hàng hợp lệ]
ChoXacNhan --> DaHuy : Nhân viên từ chối [đơn hàng không hợp lệ]

ChuaThanhToan --> DangThanhToan : Bắt đầu thanh toán
ChuaThanhToan --> DaHuy : Hủy đơn [quá thời hạn]

DangThanhToan --> DaThanhToan : Thanh toán thành công
DangThanhToan --> ChuaThanhToan : Thanh toán thất bại [thử lại]
DangThanhToan --> DaHuy : Hủy thanh toán [khách hàng hủy]

' Xử lý COD
ChuaThanhToan --> DangVanChuyen : COD [payment_method = "COD"]
DaThanhToan --> DangVanChuyen : Chuyển sang vận chuyển

' Vận chuyển
DangVanChuyen --> HoanThanh : Giao thành công
DangVanChuyen --> DangHoanVe : Giao thất bại
DangHoanVe --> ChuaThanhToan : Hoàn về thành công [COD]
DangHoanVe --> DaHuy : Hoàn về thành công [Đã thanh toán]

' Đổi trả
HoanThanh --> YeuCauDoiTra : Khách hàng yêu cầu đổi trả [trong thời hạn]
YeuCauDoiTra --> HoanThanh : Hoàn tất đổi trả

' Final states
HoanThanh --> [*]
DaHuy --> [*]

note right of ChuaThanhToan
  Database Constraint:
  status = "Chưa thanh toán"
  → payment_method = NULL
  
  Hiển thị trong:
  • Danh sách đơn chờ thanh toán
  • Tìm kiếm đơn hàng
end note

note right of DaThanhToan  
  Database Constraint:
  status = "Đã thanh toán"
  → payment_method ≠ NULL
  
  Auto Update:
  COD: Giao thành công → "Đã thanh toán"
end note

note bottom
  Triggers tự động:
  • Trừ stock_quantity khi tạo orderdetails
  • Tính subtotal = quantity × unit_price  
  • Auto xóa orderdetails khi xóa order
  • Update payment_date khi thanh toán
  
  Thống nhất với UC/AD:
  • Tìm kiếm đơn hàng: Tất cả trạng thái
  • Ghi nhận đơn hàng: DangTao → ChoXacNhan
  • Quản lý đơn hàng: Tất cả transitions
end note

@enduml

🎯 Điểm thống nhất với các sơ đồ khác

  • UC Tìm kiếm đơn hàng: Tất cả trạng thái đều có thể tìm kiếm và xem chi tiết
  • UC Ghi nhận đơn hàng: Flow từ "Đang tạo" → "Chờ xác nhận" → "Chưa thanh toán"
  • AD Quản lý đơn hàng: Các decision nodes tương ứng với transitions
  • AD Ghi nhận đơn hàng: Swimlanes tương ứng với actors trong transitions
  • Sequence Diagrams: Các hàm như processPayment(), updateOrderStatus() tương ứng với transitions
