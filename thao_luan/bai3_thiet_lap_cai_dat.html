Bài 5: Thực hành thiết lập cấu hình phần cứng, cài đặt phần mềm, chuyển đổi dữ liệu và đào tạo người sử dụng

Bài 3: Thiết lập Máy chủ, Máy trạm và Cài đặt Phần mềm Hệ thống (Chi tiết)

I. Mục tiêu

  • Thực hiện cài đặt, cấu hình hạ tầng phần cứng và phần mềm hệ thống theo cấu hình chuẩn đã xác định (Bài 2).
  • Triển khai các thành phần của Hệ thống Thông tin ABC (Next.js Frontend, Supabase Backend) theo phương án đã chọn (Cloud hoặc Self-hosting).
  • Đảm bảo môi trường kỹ thuật sẵn sàng cho việc kiểm thử hệ thống, chuyển đổi dữ liệu và đào tạo người dùng.

II. Chuẩn bị (Checklist)

  • ☑ Đã có cấu hình chuẩn: Tài liệu Bài 2 đã được phê duyệt.
  • ☑ Đã có thiết bị/dịch vụ: Phần cứng đã mua sắm hoặc tài khoản Cloud (Vercel, Supabase) đã đăng ký.
  • ☑ Đã có bộ cài đặt & license: HĐH, Driver, HQTCSDL (nếu self-host), Node.js, Docker (nếu self-host), mã nguồn ứng dụng ABC, license phần mềm cần thiết.
  • ☑ Đã có kế hoạch IP & tài khoản: IP tĩnh cho server (nếu self-host), tài khoản quản trị, tài khoản dịch vụ.
  • ☑ Đã có thông tin cấu hình: Supabase Project URL & Keys (anon, service_role), Site URL, cấu hình SMTP (nếu dùng custom SMTP).
  • ☑ Môi trường vật lý sẵn sàng: Phòng máy chủ, vị trí máy trạm, hệ thống mạng đã đi dây.

III. Thiết lập và Cài đặt theo Phương án Triển khai

Phương án 1: Triển khai Hoàn toàn trên Cloud (Vercel + Supabase Cloud)

Trọng tâm: Cấu hình dịch vụ Cloud và chuẩn bị môi trường phát triển/triển khai.

1. Cấu hình Supabase Cloud Project

  1. Tạo Project: Truy cập supabase.com, đăng nhập và tạo một Project mới. Chọn Region gần với người dùng cuối nhất (ví dụ: Singapore). Chọn gói cước (nên bắt đầu với Pro cho production).
  2. Lấy API Keys và URL:
    • Vào "Project Settings" -> "API".
    • Lưu lại cẩn thận: Project URL, anon key (public), và service_role key (secret).
  3. Cấu hình Authentication:
    • Vào "Authentication" -> "Providers": Kích hoạt các nhà cung cấp cần thiết (Email, Google, Facebook,...).
    • Vào "Authentication" -> "Settings":
      • Đặt Site URL thành URL triển khai dự kiến của ứng dụng Next.js (ví dụ: https://abc.yourcompany.com).
      • Thêm Additional Redirect URLs nếu cần (ví dụ: https://abc.yourcompany.com/auth/callback).
      • Tắt "Enable email confirmation" nếu muốn trong giai đoạn phát triển, nhưng BẬT LẠI khi lên production.
    • Vào "Authentication" -> "Templates": Tùy chỉnh nội dung email (xác nhận, mời, đặt lại mật khẩu) cho phù hợp với thương hiệu công ty.
  4. Cấu hình Custom SMTP (Khuyến nghị):
    • Vào "Project Settings" -> "Authentication" -> "SMTP settings".
    • Điền thông tin SMTP Host, Port, Username, Password của nhà cung cấp dịch vụ email (SendGrid, Mailgun, AWS SES,...).
    • Đặt Sender Email (ví dụ: noreply@yourcompany.com) và đảm bảo tên miền đã được xác thực với nhà cung cấp SMTP.
  5. Chạy Database Migrations:
    • Cài đặt Supabase CLI: npm install supabase --save-dev (hoặc global).
    • Login: npx supabase login.
    • Link project: npx supabase link --project-ref [your-project-ref] (lấy project-ref từ URL dashboard).
    • Áp dụng các migration trong thư mục supabase/migrations của dự án: npx supabase db push.
    • (Hoặc) Chạy các file SQL tạo bảng, function, policy trực tiếp trong SQL Editor trên Supabase Dashboard. Đảm bảo chạy file supabase-email-config.sql để cấu hình allowlist domain email nếu cần.
  6. Cấu hình Storage Buckets:
    • Vào "Storage" -> "Buckets".
    • Tạo các bucket cần thiết (ví dụ: avatars, product-images).
    • Thiết lập chính sách truy cập (Policies) cho từng bucket (ví dụ: cho phép public read cho ảnh sản phẩm, yêu cầu xác thực để tải lên avatar).

2. Cấu hình Vercel Project

  1. Kết nối Git Repository: Truy cập vercel.com, đăng nhập, chọn "Add New..." -> "Project", kết nối với repository chứa mã nguồn Next.js của bạn (GitHub, GitLab, Bitbucket).
  2. Cấu hình Project: Vercel thường tự động nhận diện Next.js. Kiểm tra lại Build Command (npm run build), Output Directory (.next).
  3. Cấu hình Environment Variables:
    • Vào "Settings" -> "Environment Variables".
    • Thêm các biến môi trường cần thiết từ file .env.local của bạn:
      • NEXT_PUBLIC_SUPABASE_URL (Value: Project URL từ Supabase)
      • NEXT_PUBLIC_SUPABASE_ANON_KEY (Value: Anon key từ Supabase)
      • SUPABASE_SERVICE_ROLE_KEY (Value: Service Role Key từ Supabase - QUAN TRỌNG: Đánh dấu là Secret)
      • NEXT_PUBLIC_SITE_URL (Value: URL triển khai chính thức)
      • (Các API keys hoặc biến môi trường khác nếu có)
    • Chọn môi trường áp dụng (Production, Preview, Development).
  4. Triển khai (Deploy): Vercel sẽ tự động build và deploy khi bạn push code lên nhánh chính (ví dụ: main/master) hoặc tạo Pull Request (cho Preview Deployments). Bạn cũng có thể kích hoạt deploy thủ công.
  5. Cấu hình Custom Domain: Vào "Settings" -> "Domains", thêm tên miền của bạn và làm theo hướng dẫn để cấu hình DNS records (A record, CNAME record).

Phương án 2: Triển khai Tự quản lý (Self-hosting)

Trọng tâm: Cài đặt và cấu hình chi tiết trên các máy chủ đã chuẩn bị.

1. Thiết lập Máy chủ Backend (Chạy Supabase Components)

Khuyến nghị sử dụng Linux (Ubuntu Server LTS) và Docker/Docker Compose theo hướng dẫn chính thức của Supabase.

  1. Cài đặt Hệ điều hành & Cấu hình Cơ bản:
    • Thực hiện các bước 1-4 trong Mục III của file này (Lắp đặt phần cứng, Cài HĐH Linux, Cài Driver & Cập nhật, Cấu hình IP tĩnh).
  2. Cài đặt Docker & Docker Compose:
    # Ví dụ cho Ubuntu sudo apt update sudo apt install -y apt-transport-https ca-certificates curl software-properties-common curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null sudo apt update sudo apt install -y docker-ce docker-ce-cli containerd.io sudo systemctl start docker sudo systemctl enable docker # Cài Docker Compose (kiểm tra phiên bản mới nhất trên trang chủ Docker) DOCKER_COMPOSE_VERSION=$(curl -s https://api.github.com/repos/docker/compose/releases/latest | grep '"tag_name":' | sed -E 's/.*"([^"]+)".*/\1/') sudo curl -L "https://github.com/docker/compose/releases/download/${DOCKER_COMPOSE_VERSION}/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose sudo chmod +x /usr/local/bin/docker-compose docker-compose --version
  3. Chuẩn bị Mã nguồn Supabase Self-hosting:
    git clone --depth 1 https://github.com/supabase/supabase cd supabase/docker cp .env.example .env # Mở file .env và chỉnh sửa các thông số quan trọng # Đặc biệt là các giá trị POSTGRES_PASSWORD, JWT_SECRET, ANON_KEY, SERVICE_ROLE_KEY # Nên tạo các giá trị secret mạnh mẽ, ngẫu nhiên # Ví dụ tạo secret: openssl rand -base64 32 nano .env
  4. Cấu hình Volumes và Network (Nếu cần): Đảm bảo Docker có quyền ghi vào các thư mục được ánh xạ làm volume cho PostgreSQL data, Storage,...
  5. Khởi chạy Supabase Stack:
    docker-compose pull # Tải các image mới nhất (tùy chọn) docker-compose up -d # Khởi chạy các container ở chế độ detached
  6. Kiểm tra Trạng thái Containers:
    docker-compose ps # Hoặc docker ps

    Đảm bảo tất cả các container (db, kong, gotrue, realtime, storage,...) đều đang ở trạng thái "Up".

  7. Cấu hình Firewall Máy chủ Backend: Mở các port cần thiết mà Kong gateway (mặc định 8000) và các dịch vụ khác sử dụng. Tham khảo file docker-compose.yml.
  8. Lấy API Keys và URL: Các giá trị ANON_KEY, SERVICE_ROLE_KEY được định nghĩa trong file .env. URL sẽ là địa chỉ IP hoặc tên miền của máy chủ backend này, kèm theo port của Kong (ví dụ: http://[server_ip]:8000).
  9. Chạy Database Migrations:
    • Kết nối vào container PostgreSQL: docker-compose exec db psql -U postgres
    • Sao chép nội dung các file SQL migration và chạy chúng.
    • Chạy nội dung file supabase-email-config.sql nếu cần.
  10. Cấu hình Sao lưu (Backup): Rất quan trọng! Thiết lập cron job hoặc script để thực hiện sao lưu PostgreSQL database (dùng pg_dump) và dữ liệu trong Storage volume định kỳ và lưu trữ ở nơi an toàn.

2. Thiết lập Máy chủ Frontend (Chạy Next.js App)

  1. Cài đặt Hệ điều hành & Cấu hình Cơ bản:
    • Thực hiện các bước 1-4 trong Mục III của file này (Lắp đặt, Cài HĐH Linux/Windows, Driver & Cập nhật, Cấu hình IP tĩnh).
  2. Cài đặt Node.js và npm/yarn:
    # Ví dụ cho Ubuntu (sử dụng NodeSource) curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash - sudo apt-get install -y nodejs node -v npm -v # Cài yarn (tùy chọn) # sudo npm install --global yarn # yarn --version
  3. Sao chép Mã nguồn Ứng dụng ABC:
    # Ví dụ dùng Git git clone [your-repository-url] /var/www/abc-app cd /var/www/abc-app
  4. Cài đặt Dependencies:
    npm install # hoặc # yarn install
  5. Tạo file .env.local:
    cp .env.example .env.local nano .env.local # Điền các giá trị biến môi trường # NEXT_PUBLIC_SUPABASE_URL=http://[IP_máy_chủ_backend]:8000 # NEXT_PUBLIC_SUPABASE_ANON_KEY=[Giá trị anon key từ file .env của backend] # SUPABASE_SERVICE_ROLE_KEY=[Giá trị service role key từ file .env của backend] # NEXT_PUBLIC_SITE_URL=http://[Tên miền hoặc IP của máy chủ frontend] # ... các biến khác
  6. Build Ứng dụng Next.js:
    npm run build # hoặc # yarn build
  7. Cài đặt Trình quản lý Tiến trình (PM2):
    sudo npm install pm2 -g pm2 startup # Tạo script khởi động cùng hệ thống # Chạy ứng dụng Next.js với PM2 pm2 start npm --name "abc-app" -- start pm2 save # Lưu lại danh sách process pm2 list # Kiểm tra trạng thái

    (Script start trong package.json thường là next start)

  8. Cài đặt và Cấu hình Reverse Proxy (Nginx):
    sudo apt update sudo apt install -y nginx sudo nano /etc/nginx/sites-available/abc-app.conf

    Nội dung file abc-app.conf (ví dụ):

    server { listen 80; server_name your-domain.com www.your-domain.com; # Thay bằng tên miền hoặc IP location / { proxy_pass http://localhost:3000; # Port mặc định của Next.js proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection 'upgrade'; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_cache_bypass $http_upgrade; } # Cấu hình cache cho static assets (tùy chọn) location ~* \.(?:css|js|jpg|jpeg|gif|png|ico|svg|woff|woff2|ttf|eot)$ { proxy_pass http://localhost:3000; proxy_cache_bypass $http_upgrade; expires 1y; add_header Cache-Control "public"; } }
    sudo ln -s /etc/nginx/sites-available/abc-app.conf /etc/nginx/sites-enabled/ sudo nginx -t # Kiểm tra cấu hình sudo systemctl restart nginx
  9. Cấu hình Firewall Máy chủ Frontend: Mở port 80 (HTTP) và 443 (HTTPS nếu có).
  10. Cấu hình SSL/TLS (HTTPS) với Let's Encrypt (Khuyến nghị):
    sudo apt install certbot python3-certbot-nginx sudo certbot --nginx -d your-domain.com -d www.your-domain.com # Thay bằng tên miền # Tự động gia hạn: certbot renew --dry-run (kiểm tra)

Phương án 3: Triển khai Lai ghép (Hybrid)

Thực hiện kết hợp các bước của Phương án 1 và Phương án 2 tùy thuộc vào thành phần nào được đặt trên Cloud và thành phần nào Self-host.

Lưu ý quan trọng: Cần đảm bảo kết nối mạng ổn định và an toàn giữa các thành phần trên Cloud và Self-host. Cấu hình firewall cẩn thận để cho phép traffic cần thiết giữa chúng.

V. Thiết lập Máy trạm

Quy trình thiết lập máy trạm tương đối giống nhau cho các phương án triển khai server.

  1. Cài đặt Hệ điều hành (Windows 10/11 Pro): Cài đặt sạch, đặt tên máy, join domain (nếu có).
  2. Cài đặt Driver & Cập nhật HĐH: Đảm bảo driver đầy đủ và Windows Update mới nhất.
  3. Cấu hình Mạng: Thường nhận IP động từ DHCP. Kiểm tra kết nối.
  4. Cài đặt Phần mềm Cơ bản:
    • Trình duyệt web (Chrome, Edge - phiên bản mới nhất).
    • Microsoft Office / Google Workspace tools.
    • Phần mềm đọc PDF.
    • Bộ gõ tiếng Việt.
    • Phần mềm diệt virus (quản lý tập trung nếu có).
    • Các phần mềm phụ trợ khác nếu ứng dụng ABC yêu cầu (hiếm khi cần cho ứng dụng web hiện đại).
  5. Kiểm tra Truy cập Hệ thống ABC: Mở trình duyệt, truy cập vào URL của hệ thống ABC (URL Vercel hoặc URL self-host đã cấu hình). Đảm bảo trang web tải thành công.
  6. Thiết lập Máy in, Scanner (nếu cần).

VI. Ghi chú Quan trọng

  • Tài liệu hóa: Ghi chép lại mọi bước cấu hình, thông số, tài khoản, mật khẩu. Sử dụng trình quản lý mật khẩu an toàn.
  • Kiểm tra chéo: Nên có người khác kiểm tra lại các bước cấu hình quan trọng.
  • Phiên bản: Luôn ghi rõ phiên bản của HĐH, Node.js, Docker, HQTCSDL,... đã cài đặt.
  • Bảo mật: Áp dụng các nguyên tắc bảo mật ngay từ đầu (mật khẩu mạnh, firewall, cập nhật,...).

Sau khi hoàn thành các bước trên, hệ thống đã sẵn sàng về mặt kỹ thuật cho "Bài 4: Kiểm thử Kết nối và Cấu hình Hệ thống".
