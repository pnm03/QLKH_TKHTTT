Tóm tắt Hướng dẫn Triển khai Phần mềm

Dựa trên tài liệu README-DEPLOY.md và DEPLOYMENT.md, đây là tổng quan về quy trình triển khai, các yêu cầu chuẩn bị và những lưu ý quan trọng khi triển khai ứng dụng Next.js này với Supabase lên nền tảng Vercel.

Nền tảng và Công nghệ Chính

  • Nền tảng Triển khai: Vercel
  • Backend/Cơ sở dữ liệu: Supabase
  • Framework Frontend: Next.js

Các Phương pháp Triển khai lên Vercel

  1. Qua Vercel Dashboard (Giao diện người dùng)

    Kết nối kho GitHub của bạn với Vercel, cấu hình dự án (framework, lệnh build, biến môi trường) và nhấn triển khai.

  2. Qua GitHub Actions

    Tạo dự án trên Vercel, lấy Vercel Token, Org ID, Project ID và thêm chúng làm secrets trong GitHub repository. Sau đó, chạy workflow "Deploy to Vercel".

  3. Qua Vercel CLI (Giao diện dòng lệnh)

    Cài đặt Vercel CLI (npm install -g vercel), đăng nhập (vercel login), và chạy lệnh vercel để triển khai.

Chuẩn bị Trước Khi Triển khai

  • Tài khoản Vercel: Cần có tài khoản Vercel (có thể đăng ký bằng GitHub).
  • Kho lưu trữ GitHub: Mã nguồn của dự án phải được lưu trữ trên GitHub.
  • Dự án Supabase: Cần có một dự án Supabase đang hoạt động.

  • Biến Môi trường (Environment Variables) Chi Tiết

    Đây là các biến môi trường quan trọng cần được cấu hình chính xác trên Vercel:

    1. NEXT_PUBLIC_SUPABASE_URL

    • Giải thích: Đây là URL công khai của dự án Supabase của bạn. Nó trỏ đến điểm cuối API của Supabase mà ứng dụng Next.js sẽ sử dụng để giao tiếp với backend (ví dụ: truy vấn cơ sở dữ liệu, xác thực người dùng).
    • Quan trọng: Tiền tố NEXT_PUBLIC_ trong Next.js có nghĩa là biến này sẽ được nhúng vào mã JavaScript phía máy khách (client-side). Điều này cần thiết để thư viện Supabase JS có thể truy cập API từ trình duyệt của người dùng.
    • Lấy ở đâu: Trang tổng quan (dashboard) dự án Supabase của bạn, thường trong phần "Project Settings" → "API".

    2. NEXT_PUBLIC_SUPABASE_ANON_KEY

    • Giải thích: "Anon" là viết tắt của "anonymous" (ẩn danh). Đây là một khóa API công khai, an toàn để sử dụng trong mã phía máy khách. Nó cho phép ứng dụng thực hiện các yêu cầu đến Supabase với quyền hạn của người dùng ẩn danh hoặc người dùng đã đăng nhập (sau khi xác thực). Khóa này KHÔNG cấp quyền truy cập đầy đủ mà tuân theo các quy tắc Row Level Security (RLS) bạn đã thiết lập.
    • Quan trọng: Tiền tố NEXT_PUBLIC_ làm cho nó có sẵn ở phía máy khách.
    • Lấy ở đâu: Trang tổng quan dự án Supabase, phần "Project Settings" → "API", bên cạnh SUPABASE_URL.

    3. SUPABASE_SERVICE_ROLE_KEY

    • Giải thích: Đây là một khóa bí mật (secret key) và rất mạnh mẽ. Nó bỏ qua tất cả các quy tắc Row Level Security (RLS) và cấp quyền truy cập đầy đủ vào cơ sở dữ liệu và API Supabase.
    • Quan trọng:
      TUYỆT ĐỐI KHÔNG BAO GIỜ để lộ khóa này ở phía máy khách hoặc trong mã JavaScript công khai. Nó chỉ nên được sử dụng ở phía máy chủ (server-side), ví dụ trong API routes của Next.js. Nếu bị lộ, toàn bộ cơ sở dữ liệu có thể bị xâm phạm.
    • Mục đích sử dụng: Cho các tác vụ quản trị, hoạt động backend cần quyền truy cập không hạn chế, hoặc khi thực hiện các thao tác mà RLS không phù hợp.
    • Lấy ở đâu: Trang tổng quan dự án Supabase, phần "Project Settings" → "API". Hãy cẩn thận khi sao chép và lưu trữ.

    4. NEXT_PUBLIC_SITE_URL

    • Giải thích: URL chính thức, công khai mà ứng dụng của bạn sẽ được truy cập sau khi triển khai (ví dụ: https://your-app-name.vercel.app hoặc tên miền tùy chỉnh).
    • Mục đích sử dụng:
      • Supabase sử dụng URL này để chuyển hướng người dùng sau các hành động xác thực (xác nhận email, đặt lại mật khẩu).
      • Sử dụng trong ứng dụng để tạo URL tuyệt đối (sitemap, liên kết chia sẻ).
    • Quan trọng: Đảm bảo URL này được cấu hình chính xác trong biến môi trường Vercel và trong "Site URL" của Supabase (Authentication → URL Configuration).
    • Lấy ở đâu: Vercel cung cấp sau lần triển khai đầu tiên. Nếu dùng tên miền tùy chỉnh, đó sẽ là tên miền của bạn.

    5. NEXT_DISABLE_ESLINT

    • Giải thích: Đặt giá trị là 1 (hoặc true) để vô hiệu hóa ESLint trong quá trình build trên Vercel.
    • Mục đích sử dụng: Đôi khi, quy tắc ESLint gây lỗi build trên Vercel. Đây có thể là giải pháp tạm thời, nhưng nên giải quyết vấn đề ESLint để đảm bảo chất lượng mã.
    • Giá trị đề xuất: 1

    6. DISABLE_ESLINT_PLUGIN

    • Giải thích: Tương tự NEXT_DISABLE_ESLINT, dùng để vô hiệu hóa các khía cạnh của ESLint, có thể là một plugin cụ thể của Vercel.
    • Mục đích sử dụng: Giúp tránh lỗi build liên quan đến ESLint trên Vercel.
    • Giá trị đề xuất: true

Cấu hình Sau Triển khai (Quan trọng cho Supabase)

  • Trong Supabase Dashboard:
    • Đi đến Authentication > URL Configuration: Thêm URL ứng dụng đã triển khai của bạn (chính là giá trị của NEXT_PUBLIC_SITE_URL) vào danh sách "Site URLs".
    • Đi đến API > Settings > CORS (theo README-DEPLOY.md): Thêm URL ứng dụng đã triển khai của bạn vào "Allowed Origins".

Lưu ý Quan trọng và Cấu hình Vercel

  • Framework Preset trên Vercel: Phải là Next.js.
  • Cấu hình Build trên Vercel:
    • Root Directory: ./
    • Build Command: npm run build
    • Output Directory: .next
    • Install Command: npm install
  • Production Branch: Thường là main.
  • Cập nhật NEXT_PUBLIC_SITE_URL: Sau khi Vercel cung cấp URL cho ứng dụng, hãy cập nhật biến môi trường này trong cài đặt Vercel và có thể cần triển khai lại.

Xử lý Sự cố

Cả hai tài liệu (README-DEPLOY.md và DEPLOYMENT.md) đều có phần hướng dẫn xử lý sự cố. Các điểm chính cần kiểm tra:

  • Lỗi kết nối Supabase: Kiểm tra kỹ các biến môi trường (URL, Keys) và cấu hình "Site URLs" / "Allowed Origins" trong Supabase.
  • Lỗi Build: Xem log build trên Vercel Dashboard.
  • Lỗi Runtime: Kiểm tra console của trình duyệt và log function trên Vercel Dashboard.

Ghi chú: Đây là tóm tắt dựa trên các tệp tài liệu được cung cấp. Luôn tham khảo tài liệu gốc (README-DEPLOY.md, DEPLOYMENT.md) và tài liệu chính thức của Vercel, Next.js, Supabase để có thông tin chi tiết và cập nhật nhất.
